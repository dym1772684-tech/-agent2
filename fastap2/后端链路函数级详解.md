## 1. 层次地图

| 层           | 目录 / 文件                                                                      | 核心入口函数                                       | 一句话职责                                                     | 产物                                       |
| ----------- | ---------------------------------------------------------------------------- | -------------------------------------------- | --------------------------------------------------------- | ---------------------------------------- |
| L0 进程装配     | `main.py`、`agent_bridge/bootstrap.py`                                        | `lifespan()`、`bootstrap()`                   | 一次性把 env / 包路径 / MCP 工具 / checkpointer / 身份校验器 / 中断检查全部接好 | 已编译的 `agent` 对象                          |
| L1 HTTP 接入  | `routers/agent.py`、`agent_bridge/middleware.py`                              | `_authorize_chat()`                          | 认证 → 清洗 → 装配可信身份，全在进图前完成                                  | `(thread_id, TrustedContext)`            |
| L2 会话与幂等    | `core/thread_registry.py`、`core/idempotency.py`                              | `resolve_thread_id()`、`acquire()`            | 线程归属裁决 + 同请求只执行一次                                         | 合法 thread_id / 三态裁决                      |
| L3 Agent 编排 | `agent_bridge/bootstrap.py`                                                  | `_prepare()` → `run_agent()` → `_finalize()` | 进图前准备、调图、出图后收尾                                            | `{answer, structured, thread_id, usage}` |
| L4 图执行      | `allagent2/agent/react_loop.py`、`team.py`、`graph.py`                         | `build_react_graph()` 内部五节点                  | guard→think→act→observe→finalize 循环                       | 新 state + 事件                             |
| L5 事件与观测    | `allagent2/agent/observe.py`、`core/request_id.py`、`observability/metrics.py` | `traced_node()`、`emit_event()`               | 每步一行日志 + 一组指标 + 一条 trace                                  | `state["trace"]` / `/metrics`            |
| L6 工具与 MCP  | `agent_bridge/mcp_runtime.py`、`mcp_servers/*`、`core/agent_context.py`        | `_wrap_tool()`、`_precheck()`                 | 工具跨进程调用 + 能力令牌鉴权 + 幂等                                     | 工具结果字符串                                  |
| L7 记忆       | `allagent2/session/recall.py`、`reflect.py`                                   | `recall()`、`on_turn_finished()`              | 读路径召回、写路径异步沉淀                                             | `memory_block` / 记忆表                     |
| L8 契约与配置    | `allagent2/agent/documents.py`、`allagent2/config/*`                          | `migrate_state_dict()`、`load()`              | 状态版本迁移 + 四层配置覆盖                                           | 可读的旧 checkpoint / 配置快照                   |

## 1.5 文件级职责总表

三列含义：**职责**＝这个文件存在的唯一理由；**关键定义**＝别人会 import 的东西；**被谁调用**＝上游。没有上游的文件就是「被进程直接启动的入口」。

### A. fastap2 —— 后端主进程（:8000）

```
│ fastap2（后端）               │
│  routers → agent_bridge → core│
└───────────┬──────────────────┘
            │ 单向：bootstrap 注入，不 import 反向
            ▼
┌──────────────────────────────┐
│ allagent2（智能体库）          │
│  agent → session / rag / tools│
└──────────────────────────────┘
```

1. **fastap2 可以 import allagent2，allagent2 绝不 import fastap2。**
   三条注入线代替反向依赖：
   - `middleware.set_identity_validator(fn)` —— 身份校验器
   - `observe.set_abort_check(fn)` —— 中断判定
   - `metrics_hook.set_sink(fn)` —— 指标落地

2. **`core/` 不 import `agent_bridge/` 和 `allagent2`。**
   理由：`routers/agent.py` 一 import 就会经 `agent_bridge` 触发图装配（加载模型、连 MCP）。`thread_registry` 从路由抽到 `core` 就是为了能被零依赖单测覆盖。

3. **`session/` 不 import `agent/`。**
   记忆层只认 `user_id / messages / question`，不知道图长什么样，所以两种拓扑都能复用。

**为什么 `_register_packages` 要清空再插**：`sys.path` 里残留旧条目时，`import core.xxx` 可能解析到 allagent2 的 `core`，出现「同一份代码两个模块对象、单例各自一份」的诡异问题。清除后按确定顺序插入，顺序就固定了。

**为什么 checkpointer 必须换 serde**：这个版本的 `langgraph-checkpoint-redis` 把 checkpoint 存成 RedisJSON，不走 msgpack ext 钩子。默认 JSON 复原只放行 langchain 白名单，黑板里的自定义 pydantic 模型（`Task`/`PermissionContext`/`ParsedOutput`）会退化成裸 dict，第二轮读 `TeamState` 校验必炸。白名单**不支持前缀匹配**，必须精确到符号路径，且必须用带 `_preprocess_redis_json` 的 `JsonPlusRedisSerializer` 子类。

#### `_authorize_chat()` —— 三步流水线（`routers/agent.py:83`）

```python
async def _authorize_chat(db, current, req) -> tuple:
    # ① 认证
    enforce_rate_limit(f"rl:agent:user:{uid}", 10, 60, "智能体对话")   # 超限 429 + 审计
    # ② 清洗（全部规则级，零 token，不碰 LLM）
    scan_injection(req.message)          # 命中 → 403
    guard_message(req.message, ...)      # 敏感意图 → 403
    validate_identifiers(req.elder_id)   # 格式不符 → 422
    # ③ 装配
    thread_id = await _resolve_thread_id(db, uid, req)
    bound_ids = SELECT user_elder_binding WHERE user_id=uid   # 现查，不缓存
    trusted = get_identity(req.identity_id, expected_user_id=uid)  # 复用
    if trusted is None: trusted = build_identity(...)              # 重建
    put_identity(trusted)                                          # 续 TTL
    write_audit(..., "identity:assembled", reused=...)
```

三个纯函数的分工（都在 `agent_bridge/middleware.py`）：

| 函数 | 行 | 判定依据 | 返回 |
|---|---|---|---|
| `scan_injection()` | `366` | 7 条正则：忽略以上指令 / 泄露系统提示 / 扮演管理员 / 关闭安全 / jailbreak | 命中文案或 `None` |
| `SensitiveGuard.check()` | `297` | `SENSITIVE_INTENT_KEYWORDS`（身份证/手机号/住址/病历…）且无 `allow_sensitive` | `{"code":403,"msg":...}` 或 `None` |
| `validate_identifiers()` | `380` | `^[Ee]\d{1,6}$` | 错误文案或 `None` |

**为什么拒绝用 403/422 而不是 200 包错误体**：网关、监控、告警都按状态码识别异常。200 会把「被拦截」统计成「成功」，安全事件就淹了。

**为什么 `allowed_elder_ids` 必须现查 DB**：缓存 RBAC 权限集可以省重建开销，但老人绑定关系是授权边界的核心，陈旧缓存等于越权窗口。`None` = 不限定（admin），`[]` = 显式全禁（fail-closed）。

#### `chat_with_agent()`（`routers/agent.py:160`）

```python
thread_id, trusted = await _authorize_chat(...)
permissions = build_permissions_from_identity(trusted)   # TrustedContext → dict
idem = normalize_key(uid, req.idempotency_key)
state, cached = await acquire(redis, idem)
if state == ST_DONE:   return 回放（_no_cache → 409）
if state == ST_INFLIGHT: raise 409 + Retry-After: 2
enter_context(permissions)
try:
    result = await run_in_threadpool(run_agent, ..., turn_id=req.idempotency_key)
except Exception as exc:
    release(redis, idem)                       # 失败不写 done
    if _is_llm_down(exc): raise 503            # vLLM 未启动 → 友好降级
    raise
finally:
    exit_context()                             # 防线程复用串权限
commit(redis, idem, result)
```

`_is_llm_down()`（`routers/agent.py:60`）用 `isinstance(exc, openai.OpenAIError)` 判推理后端不可达。`openai` 懒导入：包很轻，但放函数内可以避免顶层耦合。

`turn_id=req.idempotency_key`：**HTTP 幂等键与工具幂等键共用同一个标识**，排障时一个键能从入口串到 MCP 服务端。

#### `chat_with_agent_stream()`（`routers/agent.py:231`）

流式的幂等语义不同：**只能缓存结论，不能缓存过程**。

| 状态 | 处理 |
|---|---|
| `ST_DONE` | 返回 `replay_source()`：先 `event: meta`（带 `replayed:true`）再 `event: final`，结构与首跑一致 |
| `ST_INFLIGHT` | 开流**之前** 409。放在生成器里抛会变成断流，前端只看到网络错误 |
| 例外 | 没拿到 `final_payload` 就 `release`，不落 done |

`event_source()` 首帧先推 `event: meta` 带 `request_id`——前端、日志、压测报告靠这一条对齐同一次链路。响应头也回 `X-Request-Id`，抓包能直接对上。

### L2 · 会话与幂等层

#### `core/thread_registry.py`

| 函数 | 行 | 实现 |
|---|---|---|
| `new_thread_id()` | `37` | `t-{uuid4.hex[:12]}`。**不用 elder_id**——那是可枚举的劫持入口 |
| `owner_row()` | `42` | 单行查询，返回标量；单独暴露是因为失败分支要复查 |
| `resolve_thread_id()` | `50` | 无 tid → 生成 + insert；有 tid → 查属主，未登记则 insert |
| `assert_thread_owner()` | `84` | interrupt/resume 用：不存在 404，非本人 403 |

**并发正确性（幂等 L4）**：`select 判断不存在 → insert` 是典型 check-then-act 竞态，双击时两个请求都 miss 然后都 insert，后到者撞 unique 索引冒 500。这里改成**直接 insert 让唯一索引裁决**：

```
insert 成功        → 我是第一个，正常继续
IntegrityError     → rollback → 复查 owner_row
                     查到了：按「已登记」走（自己是属主就放行，别人 403）
                     还是 None：409 让客户端重试
```

#### `core/idempotency.py`（幂等 L1）

状态机两个 key 一个锁：

```
(无) --SET NX lock EX 300--> inflight --commit--> done EX 86400（同时删锁）
                              └──release──> (无)
```

| 函数 | 行 | 实现要点 |
|---|---|---|
| `normalize_key()` | `71` | `sha256(raw)[:32]` 且按 `user_id` 隔离。空键返回 `None`（本次不做幂等），否则所有没传键的请求会撞同一个 hash 互相回放 |
| `_read_done()` | `93` | 解析失败返回 `{"_no_cache": True}`——宁可少回放，不可重复执行 |
| `acquire()` | `106` | ① 先查 done（省一次写）② SET NX 抢锁 ③ **抢不到再查一次** done，覆盖「刚好在 ①② 之间完成」的窗口 |
| `commit()` | `135` | 超过 64KB 只写 `_no_cache` 标记，核心语义是「不重复执行」而非「一定回放得出内容」 |
| `release()` | `155` | **只删锁不写 done**——写 done 会让那次失败变终态，用户永远拿不到结果 |
| `peek()` | `168` | 只读排查用，不抢锁 |

**为什么必须 SET NX 不能 GET 再 SET**：两个并发请求同时 GET 都 miss，然后都去跑，双扣 token——这正是要防的事。

**Redis 挂了为什么放行**：幂等是成本与副作用护栏，不是安全边界（安全边界是鉴权）。挂 Redis 宁可多跑一次，也不能让对话不可用。

#### `/resume` 的会话级互斥（`routers/agent.py:483`）

```python

if not own_lock: raise 409 + Retry-After: 2
try:    result = await run_in_threadpool(resume_agent, ...)
finally: if own_lock: await redis.delete(lock)
```

没有这把锁，两次并发 resume 会从同一个 checkpoint 各跑一遍：工具执行两次、token 扣两次、trace 里出现两套同 seq 事件。TTL 180s 兜底防死锁。

#### `run_agent_stream()`（`702`）—— SSE 桥接

`langgraph-checkpoint-redis` 只实现了同步接口（`aget_tuple` 未实现），`astream()` 一跑就 `NotImplementedError`。所以：

```python
def _produce():                                  # producer 线程
    for chunk in agent.stream(init_state, config=config,
                              stream_mode="updates", context=ctx):
        loop.call_soon_threadsafe(queue.put_nowait, ("chunk", chunk))
```

### L5 · 事件与观测层

#### `traced_node(node)`（`observe.py:485`）—— 全链路最核心的装饰器

```python
def wrapper(state, runtime=None):
    trace = list(state.get("trace") or [])
    rnd   = int(state.get("round", 0) or 0)
    thread_id = thread_id_of(runtime)
    base = max(_max_seq(trace), _incident_seq(thread_id))   # 水位：正常轨迹 + 旁路事故

    # ① 中断检查（在 node_start 之前，seq 仍然连续）
    if should_abort(thread_id, node):
        stop = make_event("interrupted", node=node, round_no=rnd, reason=...)
        stop["seq"] = base + 1
        emit_event(stop); record_incident(thread_id, [stop])
        raise AgentInterrupted(...)

    start = make_event("node_start", node=node, round_no=rnd); start["seq"] = base+1
    emit_event(start)

    t0 = perf_counter()
    try:
        out = fn(state, runtime) or {}
    except AgentInterrupted:
        raise                                   # 必须排在 Exception 之前
    except Exception as exc:
        error = make_event("error", node=node, duration_ms=..., error="Type: msg")
        error["seq"] = base + 2
        emit_event(error)
        record_incident(thread_id, [start, error])   # 节点异常 → 返回值被丢弃 → 落旁路
        raise                                        # 异常仍原样抛，上层已有兜底文案

    duration = ...
    raw_events = out.pop("_events")                  # 节点内部事件（llm_*/tool_*）
    end_meta   = out.pop("_end")                     # node_end 附加信息
    end = make_event("node_end", node=node, duration_ms=duration, **end_meta)

    stream = [start] + raw_events + [end]
    for offset, event in enumerate(stream):
        event["seq"] = base + 1 + offset             # 统一编号
        if not event.get("node"): event["node"] = node   # 补节点名
        if event is not start: emit_event(event)

    out["trace"] = stream                            # 只返回新增，绝不带历史
    return out
```

四个必须记住的设计约束：

1. **`_events` / `_end` 是约定键**，被 pop 掉不进图状态。节点只管往里塞，不用关心编号和日志。
2. **`out["trace"] = stream` 只放新增**。trace 通道归约器是 `operator.add`，带历史会重复追加——踩过一次，单次请求事件数指数膨胀。
3. **`base` 要算上旁路水位**。中断/异常事件占用了 seq 但不进 state，不补 `_incident_seq` 续跑就会撞号（报告里出现两个 27）。
4. **`except AgentInterrupted` 必须在 `except Exception` 之前**。顺序反了中断会被当异常吞掉。

```python
#    AGENT_WRITE_TOOLS="record_medication,set_reminder"

# 3) 确认 PermissionContext.allowed_tools 放行它（默认只放 4 个只读工具，否则被 guard 当越权拦掉）
```

`migrate_state_dict` 的核心是**永不抛**：

```python
while version < CURRENT:
    fn = _MIGRATIONS.get(version)
    if fn is None: notes.append(...); break
    try: state = fn(state); notes.append(f"v{v}→v{v+1} 完成")
    except Exception as exc: notes.append(f"...失败：{exc}"); break
    version += 1
```

读旧 checkpoint 是运维路径，宁可丢掉无法识别的字段并记 note，也不能让一次会话 500。

## 4. 十个关键函数的「为什么这么写」

| 函数 | 一行实现 | 不这么写会怎样 |
|---|---|---|
| `traced_node`（`observe.py:499`） | 包一层：中断检查 → node_start → 业务 → 编号 → node_end | 用 `create_agent` 只有 model/tools 两个节点，埋不了「步骤」，只能埋「钩子」 |
| `traced_node` 的 `out["trace"] = stream` | 只返回新增事件 | trace 归约器是 `operator.add`，带历史 → 单次请求事件指数膨胀 |
| `traced_node` 的 `base = max(_max_seq, _incident_seq)` | 水位算上旁路 | 中断/异常占了 seq 但不进 state → 续跑撞号 |
| `record_incident`（`observe.py:228`） | 把进不了 state 的事件落旁路 | 节点抛异常时 LangGraph 丢弃返回值 → 「炸的那一次」在 trace 里空白 |
| `act_node` 的 `tool_ledger`（`react_loop.py:393`） | key = `tool_call_id` | 用工具名当 key，同名工具调两次互相覆盖，回答不了「这次执行过没有」 |
| `_invoke_with_retry(..., write=True)`（`react_loop.py:169`） | 写工具默认 `retries=0` | 工具已把副作用落库只是响应超时，重试 = 写两次 |
| `acquire()` 的「抢不到再查一次 done」（`idempotency.py:126`） | 覆盖并发窗口 | 刚好在查 done 与抢锁之间完成 → 客户端收到不该有的 409 |
| `release()` 不写 done（`idempotency.py:155`） | 失败只删锁 | 写 done 让失败变终态，用户永远拿不到结果 |
| `resolve_thread_id()` insert + 复查（`thread_registry.py:67`） | 让唯一索引裁决 | check-then-act 竞态 → 双击时后到者 500 |
| `mcp_runtime._call` 在当前线程签令牌（`mcp_runtime.py:97`） | 令牌当普通参数跨线程传 | `run_coroutine_threadsafe` 不传播 contextvars → 读到空上下文 → 工具 100% 403 |
| `load()` 三次校验回退（`loader.py:273`） | 逐字段回默认 | 一个拼写错误让整个服务起不来 |
| `check_*` 抽成纯函数（`middleware.py`） | 两套引擎共用判定 | 换引擎时防线要重写一份，必然漏 |

## 5. 函数级降级矩阵

| 故障 | 兜在哪个函数 | 行为 | 用户看到 |
|---|---|---|---|
| Redis 连不上（checkpointer） | `_make_checkpointer` | 降级 `InMemorySaver`，`persistent=False` | 正常回答，重启丢会话 |
| Redis 连不上（幂等） | `acquire` / `commit` / `release` | fail-open 放行 | 正常回答，可能重复执行 |
| Redis 连不上（限流） | `enforce_rate_limit` → `_fail_open` | 放行 | 正常回答 |
| Redis 连不上（中断） | `_check` / `should_abort` | 不中断 | 中断功能失效，链路不卡 |
| Redis 连不上（resume 锁） | `resume_chat` 的 `except Exception` | 放行 | 可能并发续跑 |
| 推理后端不可达 | `_is_llm_down` + `chat_with_agent` | `/chat` → 503；`/stream` → `event: error` | 友好文案，不是 500 traceback |
| MCP 服务未启动 | `connect_servers` / `_inject_mcp_tools` | 跳过该服务工具 + warning | 对应能力提示「工具不可用」 |
| MCP 令牌缺失/过期 | `_precheck` | fail-closed 403 | 工具返回「权限上下文无效」 |
| 工具执行异常 | `_invoke_with_retry` | 读工具重试 2 次；写工具不重试 | `工具执行失败：...` 进上下文 |
| 结构化输出被截断 | `finalize_node` | 从 `raw` 取文本包成 `ParsedOutput` | 纯文本回答 + `degraded` 指标 |
| team 汇总为空 | `make_aggregator` | 降级纯文本生成 + 从专员报告回填字段 | 一定拿得到回复 |
| 记忆召回失败 | `_prepare` 的 try/except | `memory_block=""` | 无记忆照常回答 |
| 记忆沉淀失败 | `on_turn_finished` / `_safe_reflect` | 线程池内自吞 | 无感知 |
| 状态版本过旧 | `migrate_state_dict` | 逐级升级 + notes | 会话能继续 |
| 配置项非法 | `load` 的三次校验 | 该字段回默认 + warning | 服务起得来，`/agent/config` 有告警 |
| 旁路日志写失败 | `record_incident` | 只告警 | 无感知（内存里还有） |
| trace 回放失败 | `get_trace` / `_finalize` debug 分支 | 返回空轨迹 + warning | 正常回答 |
| 并发续跑 | `resume_chat` 的互斥锁 | 409 + Retry-After | 明确提示稍后重试 |
| prometheus 未安装 | `metrics.install()` | 返回 False | 服务正常，`/metrics` 不挂 |
