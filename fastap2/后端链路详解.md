# 养老智能体 · 后端链路详解

> 本文描述「一次 `/chat` 请求」从进入 FastAPI 到返回答案的完整后端链路。
> 所有函数名、文件路径、字段名均取自当前代码，可对照阅读。
> 主线是 **7 层**：入口 → 准入 → 胶水层 → 图执行 → 工具跨进程 → 存储 → 旁路。
>
> 需要「哪个文件做什么、哪个函数怎么实现」的粒度，看配套文档
> [`后端链路函数级详解.md`](./后端链路函数级详解.md)。

## 1. 第 1 层：HTTP 入口（`fastap2/main.py`）

### 1.1 启动期（lifespan）

```python
@asynccontextmanager
async def lifespan(app):
    await init_db()          # Base.metadata.create_all：建缺失的表（不覆盖）
    install_logging()        # 给所有 handler 挂 rid Filter + 重写 formatter
    if metrics.install():    # prometheus_client 注册 + 注入 meter sink
        metrics.publish_runtime_state()
    yield
```

三个要点：

| 动作 | 为什么必须在这里 |
|---|---|
| `init_db()` | 原来定义了但没调用，`user_elder_binding` / `conversation_owner` / `audit_log` 表不会建 |
| `install_logging()` | 必须等 `agent_bridge`（及其 logger）都装配完；放 import 期会漏掉后建的 handler |
| `metrics.install()` | 把 `fastap2.observability.metrics._dispatch` 注入 `allagent2.guance.metrics_hook._SINK`，方向是 fastap2 → allagent2 的**单向注入**，allagent2 不反向依赖 |

### 1.2 请求中间件

```python
@app.middleware("http")
async def observability_middleware(request, call_next):
    rid = request.headers.get("X-Request-Id") or new_request_id()   # r-xxxxxxxxxxxx
    set_request_id(rid)                                            # contextvar
    ...
    response.headers["X-Request-Id"] = rid
    metrics.observe_http(method, route.path, status, elapsed)      # 用路由模板防 label 爆炸
```

- **rid 入站复用**：网关/前端已有链路 ID 时直接沿用，外部系统能串起来。
- **rid 出站回传**：浏览器、日志、压测报告三方对齐同一条链路。
- **不 reset contextvar**：SSE 的响应体在 `return` 之后才迭代，reset 会让流式阶段丢 rid；每个请求独占一个 task，结束即回收。
- **指标用 `scope["route"].path`** 而不是原始 URL：`/agent/trace/{thread_id}` 不会因为每来一个 thread 就多一个 label。

### 1.3 路由挂载

| 前缀 | 路由文件 | 说明 |
|---|---|---|
| `/api/v1` | `routers/users.py` | 注册/登录/撤销 token |
| `/api/v1` | `routers/health.py` | 健康检查 |
| `/api/v1` | `routers/elder.py` | 老人档案与健康记录 REST |
| `/api/v1` | `routers/agent.py` | **主链路**：`/agent/chat` `/chat/stream` `/trace` `/interrupt` `/resume` |
| `/api/v1` | `routers/acl.py` | 用户-老人绑定管理 |
| `/api/v1` | `routers/audit.py` | 审计查询（需 `audit:read`） |
| `/metrics` | `observability/metrics.py` | 裸挂，可选 `METRICS_TOKEN` Bearer 校验 |
| `/` `/dashboard` `/auth` | 静态 HTML | 演示前端 |

## 2. 第 2 层：准入（`routers/agent.py` + `core/`）

一次 `/chat` 在**碰 LLM 之前**要过 6 道关，全部是规则级、零 token。

### 2.1 `require_permission(PERM_AGENT_CHAT)` —— 端点级 ACL

```python
async def checker(current: CurrentUser):
    owned = ROLE_PERMISSIONS.get(current.user_role, set())
    missing = [p for p in perms if p not in owned]
    if missing:
        write_audit(..., "acl:check", decision=False, reason=f"缺少权限码: {missing}")
        raise HTTPException(403, f"权限不足:缺少 {', '.join(missing)}")
    return current
```

- 内部先走 `check_jwt`：无效/过期 → 401。
- 权限码按角色查表（`ROLE_PERMISSIONS`），不是硬编码判断。
- 拒绝也写审计 —— 越权尝试必须是可追溯的。

### 2.2 限流（`core/rate_limit.py`）

```python
await enforce_rate_limit(f"rl:agent:user:{current.user_id}", 10, 60, "智能体对话")
```

- Redis 滑动窗口，**每用户每 60 秒 10 次**。
- 防的不是攻击，是**刷 token 账单** —— 每次对话都是真金白银的模型调用。
- 超限 → 429 + 审计 `rate_limited:agent_chat`。

### 2.3 内容清洗（三道，全在 `AgentSecurityService`）

| 顺序 | 检查 | 失败返回 | 目的 |
|---|---|---|---|
| 1 | `scan_injection(message)` | 403 | 注入倾向（"忽略以上指令""输出系统提示词"） |
| 2 | `guard_message(message, {allow_sensitive})` | 403 | 敏感意图（走私数据、越权查询） |
| 3 | `validate_identifiers(elder_id)` | 422 | 标识符格式（防注入进 SQL/路径） |

关键设计：**安全拒绝一律 403/422，而不是 200 包错误 body**。这样网关、监控、前端都能用状态码直接识别，不用解析业务报文。

### 2.4 线程属主登记（`core/thread_registry.py`）

```
客户端传了 thread_id？
├─ 否 → 生成 t-{uuid} → 直接 insert → 撞 unique 就 rollback + 409
└─ 是 → 先 select 属主
         ├─ 行不存在 → insert（撞 unique 说明并发对手刚建好 → rollback 复查属主）
         └─ 行存在   → user_id 不匹配 → 403
```

**为什么不是 select-then-insert**：两个并发请求（客户端重试/双击）同时 select 都拿不到行，然后都 insert，后者撞 unique 索引 → `IntegrityError` 冒成 500。改成**直接 insert 让数据库裁决**，撞了就回滚复查 —— 能读到行说明别人刚登记成功，按"已登记"路径继续走。

### 2.5 可信身份装配（`core/identity.py`）

```
req.identity_id 存在？
├─ 是 → get_identity(id, expected_user_id=当前用户)
│        ├─ 找到 → 刷新 allowed_elders（**从 DB 现查，不用缓存**）+ session_id → put 续 TTL
│        └─ 找不到/过期/属主不符 → 走重建
└─ 否 → build_identity(user_id, role, session_id=thread, bound_elder_ids)
          → put_identity 写 Redis（identity:{id}, TTL 900s）
```

- `allowed_elders`：admin → `None`（不限定）；普通用户 → DB 里绑定关系的最新快照。
- 权限边界**永远以 DB 现查为准**：缓存只省 RBAC 重建，绑定关系不做陈旧缓存。
- 产出的 `identity_id` 随请求进图，`identity_guard` 在**每次模型调用前**复验 —— 登出/降权/锁定后，正在跑的长链路会在下一个模型调用点被斩断。

### 2.6 幂等三态（`core/idempotency.py`）

```
没传 idempotency_key → 直接执行（可选能力，不强迫调用方改造）
传了：
  ① 先查 done  → 命中则回放缓存响应（Idempotent-Replay: true），零 token
  ② SET NX 抢锁（inflight，TTL 内独占）
  ③ 抢不到 → 再查一次 done（覆盖"刚好在①②之间跑完"的窗口）
       ├─ done   → 回放
       └─ inflight → 409 + Retry-After: 2
执行失败 → release（不写 done，否则用户永远拿不到这一轮结果）
```

`/chat/stream` 的差异：流式过程无法缓存，`done` 用 `meta` + `final` 两个事件**瞬间回放**；`inflight` 必须在**开流前**返回 409（在生成器里抛会变成断流，前端只会看到网络错误）。

## 3. 第 3 层：胶水层（`agent_bridge/bootstrap.py`）

这一层的存在意义：`allagent2` 是纯 Agent 库（不认识 FastAPI/MySQL/Redis），`fastap2` 是业务后端。**所有跨界的接线都收敛在 `agent_bridge`**，依赖方向单向（fastap2 → allagent2）。

### 3.1 `bootstrap()` —— 一次性装配

```
_bstate.ready? → 直接返回（幂等）
锁外双检 → 临界区：
  _load_envs()            读 allagent2/core/key.env、fastap2/core/key.env、database/mysql.env
  _register_packages()    把 allagent2 挂进 sys.modules 的别名空间
  _inject_mcp_tools()     连 8001/8002/8003 → list_tools → 包装成 StructuredTool
                          同名本地工具被 MCP 版本替换（去重，避免双份）
  _make_checkpointer()    RedisSaver（serde 白名单放行 Task/PermissionContext/ParsedOutput）
                          连不上 → 降级 InMemorySaver（重启丢会话，但服务能跑）
  _inject_zero_trust()    identity validator + AGENT_PROFILES 注入 allagent2
  _inject_abort_check()   Redis 中断标记判定注入 observe.set_abort_check
  拓扑选择：
    AGENT_TOPOLOGY=team    team.make_team_graph（supervisor → 3 专员 → aggregate）
    其他（默认）           graph.make_graph
                            └─ AGENT_ENGINE=react（默认）→ build_react_graph
                            └─ AGENT_ENGINE=create_agent → 官方封装（回退路径）
```

失败处理：`except BaseException` 记录到 `_state.error`，`/agent/status` 能直接看到装配为什么失败，而不是启动静默成功、请求全 500。

### 3.2 `_prepare()` —— 进图前的准备

按顺序做 5 件事：

```
① 急救短路（规则级，零 token，不进图）
   EMERGENCY_KEYWORDS 命中 → 直接返回 EMERGENCY_REPLY + emergency_flag=True
   
② 权限上下文（fail-closed）
   permissions 注入 > elder_id 推断 > PermissionContext(allowed_elder_ids=[])
   —— 调用方什么都没给时，显式禁止一切老人数据访问，而不是放行

③ 初始 state
   messages=[HumanMessage(question)]
   permissions=perm_ctx
   turn_id=客户端幂等键 或 turn-{uuid}
        └─ 用途：写工具幂等键 = {thread_id}:{turn_id}:{tool_call_id}
           HTTP 层与工具层用同一个标识，排障时一个键从入口串到 MCP 服务端
   identity_id（零信任复验用）
   schema_version（新会话直接按当前版本落盘）

④ 记忆召回（读路径，fail-open）
   recall(user_id, question, elder_hint) → memory_block 注入 state
   消费端：team 拓扑由 supervisor 拼进规划 prompt；single 拓扑由 dynamic_prompt 拼进 system prompt
   MySQL/Chroma 任何故障 → 返回空块，退化为"无记忆"，绝不挡回答

⑤ 运行时上下文 config_schema(thread_id, current_elder_id, permissions, locale)
   config = {"configurable": {"thread_id": thread_id}}
```

### 3.3 执行

| 模式 | 实现 | 说明 |
|---|---|---|
| 同步 | `_state.agent.invoke(init_state, config, context=ctx)` | `/chat` 用，跑在 `run_in_threadpool` 里 |
| 流式 | `agent.stream(..., stream_mode="updates")` 丢**线程池** + `asyncio.Queue` 桥接 | 见 3.4 |

为什么流式要桥接：`langgraph-checkpoint-redis` 只实现了同步接口（`aget_tuple` 未实现），直接 `astream()` 必 `NotImplementedError`。所以：producer 线程跑同步 `stream()`，用 `loop.call_soon_threadsafe` 把 chunk 塞队列；消费侧 `await queue.get()` 逐个 yield。

**contextvars 陷阱**：`loop.run_in_executor` **不传播** contextvars，MCP 网关取不到权限令牌会全线 403。所以必须显式 `contextvars.copy_context()` 再 `request_ctx.run(_produce)`。

### 3.4 token 计量（请求级回调）

```python
def _with_usage_callback(config):
    acc = TokenAccountant()
    cb = TokenAccountingCallback(acc)
    cfg["callbacks"] = [cb]        # LangGraph 会把 callbacks 传播进所有节点（含嵌套子图）
    return acc, cfg
```

为什么不能事后扫 `messages`：team 拓扑下专员子图的消息**不出黑板**（`messages` 通道只有 aggregate 手工构造的裸 AIMessage），supervisor/aggregate 的 structured 调用更不产生消息 → 扫 messages 恒为 0。回调节点级计量 single/team、invoke/stream 通吃。

### 3.5 `_finalize()` —— 出图后处理

```
① 结构化优先
   single → result["structured_response"]（response_format=ParsedOutput）
   team   → result["final"]（aggregate 写进黑板）
   取 answer + 按 PARSED_FIELDS 逐字段抽

② 兜底（绝不能拿 system 消息冒充答案）
   没有 answer → 倒序找最后一条 type=ai 且有 content 的消息
   还没有 → "（智能体已完成本轮解析，但未生成可展示的最终回复，请换个问法重试）"

③ 急救标记透传（链路内 middleware 短路时置位）

④ token 汇总
   回调计量优先 → 无回调则 collect_usage(messages)（按 AIMessage.id 去重）
   → get_global_accountant().merge() 累计
   → append_usage_log() 落 JSONL 账本（重启不丢，可回读）

⑤ 记忆沉淀（写路径，fire-and-forget）
   on_turn_finished(user_id, thread_id, messages, question, answer)
   → 登记轮次（快 SQL，同步）
   → 达门槛则 submit 到专用线程池做反思（慢 LLM 调用）
   内部全异常自吞：沉淀失败绝不影响本响应
```

## 4. 第 4 层：图执行（`allagent2/agent/react_loop.py`）

### 4.1 拓扑

```
        START
          │
          ▼
       ┌──────┐
       │guard │ ──急救命中 / 身份失效──→ finalize
       └──────┘
          │ 通过
          ▼
       ┌──────┐  有 tool_calls 且 round < max_rounds
       │think │ ────────────────────────────→ act
       └──────┘                                  │
          │ 无 tool_calls / 达轮次上限             ▼
          │                                   ┌────────┐
          │                                   │observe │
          │                                   └────────┘
          │                                        │
          │                                        └──→ think（回到思考）
          ▼
      ┌──────────┐
      │finalize  │ → END
      └──────────┘
```

`max_rounds` 来自 `allagent2/config` 的 `agent.max_rounds`（默认 6），达上限强制收尾，不会无限调工具。

### 4.2 五个节点各做什么

| 节点 | 职责 | 关键实现 |
|---|---|---|
| `guard` | 急救关键词 / 必填槽位 / 身份复验 / 权限 | 复用 `middleware` 的纯函数 `check_emergency` `check_slot` `check_identity`，命中即 `phase=emergency/identity_blocked`，条件边直接跳 finalize |
| `think` | 组装 prompt → 调模型 → 解析工具决策 | 超过 30 条消息压成 16 条（插一条"较早 N 条已省略"的 SystemMessage）；唯一模型调用点 |
| `act` | 权限 → 台账去重 → 重试 → 脱敏 → 截断 → 回填 ToolMessage | 见 4.4 |
| `observe` | 汇总本轮工具结果，决定回思考还是收尾 | 成功/异常计数进事件 |
| `finalize` | 结构化输出（`response_format=ParsedOutput`） | 结构化失败 → 降级用最后一条 AI 文本，事件标 `structured_end` 降级 |

### 4.3 `traced_node` —— 每个节点外面的一层包装

所有 5 个节点都注册成 `traced_node("xxx")(xxx_node)`，这一个装饰器同时承担 4 件事：

| 能力 | 实现 |
|---|---|
| **事件流** | `node_start` 前 + (llm/tool/guard/observe 中间事件) + `node_end`，每条带 `seq/ts/duration_ms`；`node_end` 带 `next_action` 说明"下一步做什么" |
| **指标** | `emit_event` 拆成 `_log_event` + `_meter_event`，后者把 6 类事件派发到 `meter()`（node 耗时/次数、llm token/成本、tool 耗时/错误、guard 命中、中断） |
| **中断** | 节点入口 `should_abort(thread_id, node)` → 抛 `AgentInterrupted`，图停在上一 superstep |
| **失败可见** | 节点抛异常时 LangGraph **丢弃节点返回值**，error 事件进不了 `state["trace"]` → 改为落旁路（内存 deque + `trace_incidents.jsonl`），`get_trace` 再合并回来 |

seq 编排水位取 `max(_max_seq(trace), _incident_seq(thread_id))` —— 中断/异常事件占用序号但不进 state，不补水位会导致续跑撞号。

### 4.4 `act` 节点的完整判定顺序

```
for call in 模型返回的 tool_calls:
    ① 权限：check_tool_permission(call, state, runtime)
         越权 → 回填 ToolMessage("无权…") + board 记录 + tool_events(is_error=True)，**不执行**
    ② 工具存在性：tool_map.get(name)
         不存在（MCP 未连）→ 回填"工具 X 当前不可用"，不抛异常
    ③ 幂等台账：tool_ledger[tool_call_id] 命中？
         命中 → 直接复用上次结果回填 ToolMessage，事件打 reused=True，**一次都不碰工具**
    ④ 执行：_invoke_with_retry(tool, args, retries, write=is_write_tool)
         write=True 且工具未声明 idempotency_key → retries=0（禁止盲重试）
         write=True 且声明了 → 自动注入 {thread_id}:{turn_id}:{tool_call_id}
         读工具 → 重试 2 次，指数退避 0.3/0.6s
    ⑤ 脱敏：mask_pii(结果)（手机号/身份证/地址）
    ⑥ 截断：超 4000 字符截断（防一次查询撑爆窗口）
    ⑦ 写黑板：tool_results[name] + tool_ledger[call_id]
```

`tool_results` 按工具名、`tool_ledger` 按 `tool_call_id` —— 后者回答的是"**这个具体调用**执行过没有"，是 checkpoint 恢复/续跑不重复执行工具的依据。

## 5. 第 5 层：工具跨进程（`agent_bridge/mcp_runtime.py`）

### 5.1 装配

```
connect_servers({"elder": 8001, "life": 8002, "knowledge": 8003})
  → streamablehttp_client(url) 建常驻会话（后台事件循环线程）
  → session.list_tools()
  → 每个 MCP 工具用 _wrap_tool 包成 LangChain StructuredTool
  → 参数 schema 转 pydantic（**剔除 agent_context**，LLM 看不到它）
```

### 5.2 调用时的令牌注入

```
tool.invoke(args)
  → 同步包装器从 contextvars 读 _AccessContext（谁、什么角色、能查哪些老人、能用哪些工具）
  → make_context_token(ctx)：HMAC 签名，含 user_id / role / allow_sensitive /
                              allowed_elder_ids / allowed_tools / rid / iat / exp
  → kwargs["agent_context"] = token
  → session.call_tool(name, kwargs)
```

**为什么不用 HTTP header**：`streamablehttp_client` 是常驻连接，连上后改不了 header。令牌放进工具参数是应用层扩展，MCP 协议本身允许任意参数，不违反规范；`_schema_to_pydantic` 会把该参数从对外 schema 剔除，模型无法伪造。

### 5.3 服务端（`mcp_servers/data_gateway.py`）

```
verify_context_token(agent_context)
  ├─ 验签失败/过期 → 拒绝
  ├─ allowed_tools 存在且不含本工具 → 拒绝
  └─ allowed_elder_ids 校验（对象级）
→ 执行 SQL（异步引擎 + 参数化）
→ _mask_pii 二次脱敏（不信任调用方）
→ _audit_bg 异步写审计（user_id / action / resource）
```

**双重脱敏**：`act` 节点脱敏一次（为了日志和上下文安全），网关再脱敏一次（因为不信任任何调用方）。

### 5.4 知识库工具 → RAG 内部链路

```
search_knowledge_base(query)         MCP :8003
  → search_knowledge(query, top_k=4)  （同步阻塞，丢线程池保住事件循环）
  → rag.search():
       ① HyDE 假设回答生成（API 大模型）→ 与双路召回**并行**提交，隐藏延迟
       ② 词法召回（BM25 风格，子块粒度）      ┐
       ③ 向量召回（embedding + Chroma）      ├ 三路
       ④ HyDE 向量召回（假设回答的 embedding）┘
       ⑤ 融合：relative 加权（W_LEXICAL / W_VECTOR / W_HYDE=0.3，空路自动回退）
       ⑥ 重排：bge-reranker（加载失败/预测异常 → 回退融合排序，不降级失败）
       ⑦ 父块还原 → 返回 [{text, source}]
  → 指标落 rag_metrics.jsonl（latency / rerank_used / vector_degraded / hyde_used）
```

任一环节失败都**降级而不报错**：HyDE 无 key/超时 → 空路；向量失败 → 只用词法；重排失败 → 用融合分。检索质量下降但回答不中断。

## 6. 第 6 层：存储

### 6.1 MySQL（事实源）

| 表 | 用途 |
|---|---|
| `user` / 角色 | 账号、bcrypt 密码、`user_role` |
| `elder` | 老人档案 |
| `health_record` | 血压/血糖等监测记录（工具查的就是这里） |
| `user_elder_binding` | 用户-老人授权绑定（对象级 ACL 依据） |
| `conversation_owner` | 会话线程属主（防劫持，`thread_id` unique） |
| `audit_log` | 审计：谁、什么动作、什么资源、放行还是拒绝、原因 |

### 6.2 Redis（快状态）

| 键 | TTL | 用途 |
|---|---|---|
| `checkpoint:*`（RedisSaver） | 无 | 每个 superstep 一份图状态 |
| `idem:{user}:{key}` | 24h | 幂等三态 + 响应缓存 |
| `rl:agent:user:{uid}` | 60s | 滑动窗口限流 |
| `agent:abort:{tid}` | 600s | 中断标记 |
| `identity:{id}` | 900s | 可信身份（含 allowed_elders 快照） |
| `agent:resume-lock:{tid}` | 180s | 续跑互斥（防并发双跑） |

**checkpointer 的坑**：RedisSaver 存 RedisJSON，自定义 pydantic 模型必须配 `JsonPlusRedisSerializer(allowed_json_modules=[精确符号路径])`，白名单**不支持前缀**，也不能用基类 `JsonPlusSerializer`（缺 `_preprocess_redis_json`）。

## 8. 一次请求的完整时序（30 步）

| # | 位置 | 动作 | 失败时 |
|---|---|---|---|
| 1 | `main.py` middleware | 生成/复用 rid，写 contextvar | - |
| 2 | `require_permission` | JWT 校验 | 401 |
| 3 | 同上 | 角色 → 权限码比对 | 403 + 审计 |
| 4 | `_authorize_chat` ① | 限流（10/60s） | 429 + 审计 |
| 5 | `_authorize_chat` ② | 注入扫描 | 403 + 审计 |
| 6 | 同上 | 敏感意图检查 | 403 + 审计 |
| 7 | 同上 | 标识符格式校验 | 422 + 审计 |
| 8 | `_resolve_thread_id` | 属主登记（insert + 复查） | 403 / 409 |
| 9 | `_authorize_chat` ③ | 可信身份装配/复用 → Redis | 内部重建 |
| 10 | `idem_acquire` | 幂等三态判定 | 409 / 回放 |
| 11 | `enter_context(permissions)` | 权限上下文进 contextvars | - |
| 12 | `run_in_threadpool` | 切到 worker 线程（不阻塞事件循环） | - |
| 13 | `bootstrap()` | 首次请求触发装配（之后直接返回） | 记录 error，503 |
| 14 | `_prepare` ① | 急救关键词短路 | 命中则直接返回，跳过 15-27 |
| 15 | `_prepare` ② | 权限上下文 fail-closed | - |
| 16 | `_prepare` ③ | 初始 state（messages / turn_id / identity_id / schema_version） | - |
| 17 | `_prepare` ④ | 记忆召回 → `memory_block` | fail-open 空块 |
| 18 | `_with_usage_callback` | 挂 token 回调 | 回退消息扫描 |
| 19 | `guard` 节点 | 急救/槽位/身份/权限 | 跳 finalize |
| 20 | `think` 节点 | 压缩历史 → `build_prompt` → 模型调用 | 异常 → error 事件 + 旁路 |
| 21 | `think` 条件边 | 有 tool_calls？轮次未超？ | 否则 finalize |
| 22 | `act` 节点 | 权限 → 台账 → 执行 → 脱敏 → 截断 | 工具异常 → ToolMessage 回模型 |
| 23 | `mcp_runtime` | contextvars → HMAC 令牌 → `call_tool` | 重试 2 次后回填失败文案 |
| 24 | MCP server | 验签 → ACL → SQL → 脱敏 → 审计 | 拒绝/异常以文本返回 |
| 25 | `observe` 节点 | 汇总工具结果 | - |
| 26 | 循环 20-25 | 直到无 tool_calls 或达上限 | - |
| 27 | `finalize` 节点 | 结构化输出 | 降级用最后一条 AI 文本 |
| 28 | `_finalize` | 结构化提取 → 兜底 → token 汇总 → 记忆沉淀 | 各自 try/except |
| 29 | `idem_commit` | 写 done + 缓存响应 | 失败只影响重放能力 |
| 30 | 返回前 | `ApiResponse.success(data)` + `X-Request-Id` | - |

流式（`/chat/stream`）的差异只在 12 和 29 之间：首帧先推 `event: meta {request_id}`，图执行改为 producer 线程 + Queue 桥接，节点名翻成中文话术（`_PHASE_LABELS`）逐帧推 `event: phase`，最后 `event: final`。

## 9. 降级矩阵（这层坏了会怎样）

| 组件 | 故障表现 | 系统行为 |
|---|---|---|
| Redis 连不上 | checkpointer 构造失败 | 降级 `InMemorySaver`（会话不持久化），`/agent/status` 的 `persistent=false` |
| Redis 中途挂 | 幂等/限流/中断标记读写失败 | 幂等 fail-open（照常执行）、限流放行、中断失效 |
| MCP 服务未启动 | `list_tools` 拿不到 | 该服务工具缺失，模型收到"工具不可用"文本；`/agent/status` 的 `tools_count` 变少 |
| LLM 不可达 | `invoke` 抛连接异常 | HTTP 503 + 审计 `llm:unavailable`；SSE 已开流则推 `event: error` |
| 结构化输出失败 | `with_structured_output` 解析失败 | 降级用最后一条 AI 文本，事件标 `structured_end` 降级 |
| 单次工具失败 | 超时/异常 | 重试 2 次（写工具不重试）→ 失败文案回填给模型自行判断 |
| 记忆系统故障 | MySQL/Chroma 异常 | recall 返回空块、reflect 跳过，**绝不影响回答** |
| RAG 向量路失败 | embedding/Chroma 异常 | 降级纯词法召回，`vector_degraded=true` |
| 重排模型加载失败 | bge-reranker 异常 | 回退融合排序，不报错 |
| 指标包缺失 | `prometheus_client` 未安装 | `/metrics` 不挂载，服务照常启动 |
| 审计表写失败 | DB 异常 | 只打结构化日志，业务继续 |
| 节点抛异常 | 任意节点 | 事件进旁路 + `AgentInterrupted` 之外的异常原样抛给上层兜底文案 |

## 10. 十条硬约束（改代码前必读）

1. **依赖方向单向**：`allagent2` 绝不 import `fastap2`。需要反向能力（identity 校验、中断判定、指标 sink）一律用**注入**（`set_identity_validator` / `set_abort_check` / `metrics_hook.set_sink`）。
2. **`except AgentInterrupted` 必须写在 `except Exception` 之前**，否则中断会被当成 error 记，还会被上层兜底文案吞掉。
3. **`trace` 用 `operator.add` 归约，节点只能返回新增事件**，返回含历史的列表会指数膨胀并重复执行工具。
4. **seq 水位取 `max(_max_seq(trace), _incident_seq(tid))`**，中断/异常事件占号但不进 state，不补水位续跑会撞号。
5. **`invoke(None, config)` 才是断点续跑**：传 state 会追加消息，等于新开一轮。
6. **裸 `ThreadPoolExecutor` 不传播 contextvars**，rid 会变 `-`；只有 `anyio.to_thread`（starlette 的 `run_in_threadpool`）才传播。跨线程传权限上下文必须显式 `copy_context()`。
7. **写工具默认不重试**。加"记录服药"这类工具时：`@mcp.tool() @idempotent`，函数签名带 `idempotency_key: str = ""`，并设置 `AGENT_WRITE_TOOLS=工具名`。否则每次超时重试就是重复写库。
8. **幂等键不能用消息内容 hash**：用户真会说"再讲一遍"，会被误吞。
9. **MCP 令牌走工具参数不走 header**：`streamablehttp_client` 是常驻连接，连上后改不了 header。
10. **重依赖延迟导入**：`torch` / `chromadb` 必须在使用时导入，顶层 import 曾与 database 原生扩展段冲突直接段错误；HF 相关必须先设 `HF_ENDPOINT=https://hf-mirror.com`。
